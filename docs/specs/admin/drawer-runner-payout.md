## Purpose
Show one runner payout line and let any authorized admin (row 77 rule applied to runner payouts) (1) review an `on_hold` item reimbursement: approve an amount up to the cap, or reject with a note (rows 105, 106, 108, 135); only as an explicit exception, approve above the runner's purchase limit with a recorded reason (row 142); (2) send an unpaid payable item line back for review when the receipt does not match (row 105); (3) record the manual M-Pesa payout of this line alone; (4) after it is paid, record an append-only correction, reversal or re-sent payout (row 107, same rules as refund corrections, row 100); (5) on CANCELLED/FAILED tasks, see the task's combined exposure and override it with a reason (row 136).

## Entry / exit
- Entry: `p-runner-payouts` row; the task drawer's new `Runner payouts` section (SA-3, below); `p-payout-requests` drawer links.
- Head title: `Runner payout`. Close: ✕, overlay, ESC. Unsaved form → A-08 `Discard this decision?` / `What you entered will be lost.` / `Back` · `Discard`.
- `Open task` (`.btn .btn-text`) → task drawer; `Open runner` → `drawer-runner`.

## States
| Effective status (stored) | Sections |
|---|---|
| `on_hold` | Summary, Amounts, Receipt, **Review form**, Activity |
| `payable` (`payable`) | Summary, Amounts, Receipt, **Payout form**, `Send back for review` (item lines only), Activity |
| `paid` | Summary, Amounts, Receipt, Payout (read-only), Corrections, `Record a correction`, Activity |
| `payable` (stored `paid`, latest adjustment a reversal) | as `paid`; chip `Payout reversed`; the standing action is the **re-send form** (no mark-paid) |
| `rejected` | Summary, Amounts, Receipt, Decision (read-only), Activity |

## Override note: one field for both scopes (correction 2026-10-14)
The API takes **one** `exposureOverrideNote` per request and applies it to every cap that binds (task and item scope), recording one override row per bound scope. The form therefore has one `Why go over the cap?` field. After a 409 it shows the figures of that 409's scope; if a later request (sent without a note because the amount was within the first cap) returns a 409 with the other scope, the figures switch to that scope and the same field is required. The earlier wording "asks for its own note" in §5.2a is superseded.

## SA-3: task drawer section `Runner payouts`
In the task drawer (`drawer-task`), for tasks at CONFIRMED or later and CANCELLED/FAILED tasks with lines: `.drawer-label` `Runner payouts`, one `.drawer-row` per line from `GET /runner-payouts?errandId=` (`Runner fee` / `Item reimbursement` → amount + chip), row click → this drawer. Hidden when there are no lines.
